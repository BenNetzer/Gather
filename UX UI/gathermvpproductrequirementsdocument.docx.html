Gather – MVP Product Requirements Document

Oct 25, 2026 ·

Summary

Gather is a mobile-first web app that shows Jerusalem's culture and leisure events in one place, as a list or on a map. It combines institutional events (bars, cultural centers, the municipality) with private and community events (yard sales, home workshops, jam sessions, house parties).

v1 is a working product built by a team of three within the course: events collected from 1–3 public sources, a date filter, and a simple form for private events. A fuller toolkit for private hosts is planned for a later phase.

In v1 we will first approach the issue from the “events hunters” side - we will add the events using the script and provide value for users, and then it will increase the value of a future event that will be uploaded to Gather.

Problem

Discovering events in Jerusalem depends on luck: which channels you belong to and what an algorithm chooses to show you. Events are scattered across dozens of WhatsApp groups, Facebook pages and Instagram stories that disappear. Planning for today or the coming weekend takes long searching, and small events rarely surface.

Newcomers to the city are hit hardest: first- and second-year students and young people who recently moved. Tourists face the same gap. Gather is one place to look for events on purpose.

Alternatives & Differentiation: Current alternatives require checking fragmented sources (e.g., the National Library website, Rehavia Facebook groups, and Meydale's Instagram). Gather's differentiator: Gather centralizes all these events into one platform, making discovery and planning effortless.

Target market and core use case

  • Audience: young people aged 20–35 in Jerusalem — students (Hebrew University, Bezalel and others), local young people, and tourists or temporary residents.
  • Focus neighborhoods: Nachlaot, the city center and Mahane Yehuda market, Rehavia, Baka, the German Colony and Talbiyeh, and the campuses.
  • Curation: events for young people only. Family, toddler and senior events wait for a later version with target-audience filters.
  • Core use case: short-term planning. A user checks on Wednesday evening or Friday morning what is on today or this weekend. Spontaneous discovery nearby is secondary.

v1 product experience

  • No sign-up: browsing, filtering and event pages are open to everyone.
  • Views: the list view opens by default, with upcoming events sorted by date. The map view shows the same events as pins at their locations. The user switches between the two.
  • Date filter: today, this week, this weekend. To avoid an empty screen, the default is today only when more than 10 events are live today; otherwise it is this weekend.
  • Event page: name, date, time, location and a link to the original source. Private events show the poster's description instead of a source link.
  • Freshness: past events are hidden, and an event listed by several sources appears once.

Content supply

Daily collection run

  1. A team member runs the collection over 1–3 public sources, using the team's existing subscriptions (no paid APIs).
  2. A language model extracts each listing into structured fields: title, date, start time, venue or address, and source link. A listing that covers several dates is split into separate events.
  3. The venue name is matched against a fixed Known Venues table of Jerusalem venues, which supplies the exact address and coordinates.
  4. Rule-based checks block any event with no date, or with a field that does not appear verbatim in the source text.
  5. Duplicates across sources are merged.
  6. The remaining events go to a staging table, where a team member reviews, corrects and publishes them.

Flyers and story screenshots taken from social networks are out of v1, under the social-network constraint.

Private posting

A simple form: event name, date, start time (end time optional), address, short description, and free or paid (with an optional external payment link, such as Bit or PayBox). Whether submissions publish immediately or after team approval is open.

Data model (v1)

  • Events: id, title, description (private events), start time, end time (optional), address, latitude and longitude, source link (collected events), origin (collected or private), free or paid with price text and payment link, and status (draft in staging, active, cancelled, past).
  • Known Venues: name, address, latitude and longitude for Jerusalem venues.

Later phase: host toolkit

The host toolkit turns private posting into an event-management tool, so hosts spread Gather by sharing its links to run their own events. It relies on SMS verification, which typically requires a paid service — outside v1's no-paid-API constraint.

  • Privacy tiers, chosen by the host:
  1. Public: exact pin on the map, no registration.
  2. Auto-reveal: approximate area on the map; a guest who registers with a verified phone gets the exact address at once, while places remain.
  3. Host approval: approximate area; the guest sends a request with a short intro or social profile link, and gets the address after the host approves.
  • Location obfuscation: the exact address is stored encrypted on the server and never sent to the browser. The map shows a fixed point 100–250 m away, inside the sub-neighborhood (for example, Nachlaot – Nissim Bachar area), with a translucent circle.
  • Verification and management: one-time SMS codes for hosts and guests; a share link; and a passwordless magic link for the host to see registrants, approve requests and edit the event.
  • Capacity: when registrations reach the limit, the event is marked Full and leaves the public map and list. Visitors with a direct link see "Registration closed".
  • No-show protection: free events with a limit can allow 20% overbooking. Effective capacity = round(limit × 1.2); a limit of 20 closes at 24.
  • Auto-reopen: each confirmation includes a one-click cancel link. A cancellation that brings registrations below effective capacity, before the event starts, returns the event to the map.
  • Retention: after registering, a non-blocking offer to get updates on similar events, using the verified phone number.
  • Phase metrics: share of visitors who arrive through a host's shared link and go on to browse other events; self-cancellation rate; host satisfaction with turnout versus capacity.
